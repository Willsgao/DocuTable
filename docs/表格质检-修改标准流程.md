# 表格质检 — 修改标准流程

你只负责：**随口说目标或现象**（不必记命令、不必填 scope）。  
AI 负责：识别是否在改表格质检 → 自动写 scope → 跑防护 → 小步改码 → 汇报结果。

---

## 随机提问模式（推荐）

你平时怎么问都行，例如：

- 「第 5 页有表头怎么还报 C01？」
- 「折行那个规则再宽松一点」
- 「UI 上一个红都没有，是不是没挂上？」

**你不需要：**

| 不必做 | 谁来做 |
|--------|--------|
| 填 `anomaly-change-scope.txt` | Agent 用 `init-scope "你的原话"` 自动生成 |
| 跑 preflight / verify | Agent 改前改后自动跑 |
| 读契约文档 | Agent 改规则前自己读 |
| 按固定格式提问 | `.cursor/rules/table-qa-intent-router.mdc` 自动识别意图 |

**Agent 识别到表格质检相关时**会读 `.cursor/skills/anomaly-rules-change/SKILL.md` 并走全流程；无关问题（样式、部署等）则正常回答，不打扰你。

## 标准流程（每次修改必走）

```
┌─────────────┐
│ 1. 你提目标  │
└──────┬──────┘
       ▼
┌─────────────┐     失败则停止，先修环境/旧回归
│ 2. preflight │  python -m codes.v2_steps.anomaly_change_guard preflight
└──────┬──────┘
       ▼
┌─────────────┐
│ 3. 写 scope  │  填写 anomaly-change-scope.txt（见模板）
└──────┬──────┘
       ▼
┌─────────────┐
│ 4. 小步改码  │  默认只动 table_anomaly_rules.py
└──────┬──────┘
       ▼
┌─────────────┐     失败则回滚或继续修，不得宣称完成
│ 5. verify    │  python -m codes.v2_steps.anomaly_change_guard verify
└──────┬──────┘
       ▼
┌─────────────┐
│ 6. 你确认    │  看报告 + 必要时重开 PDF 看 🔴
└─────────────┘
```

## 改动范围（scope）

复制 `anomaly-change-scope.template.txt` → `anomaly-change-scope.txt`，每次任务填一次：

```text
task: 修复 xxx
allowed:
  - codes/v2_steps/table_anomaly_rules.py
forbidden:
  - codes/ui/**
  - codes/pdf_extractor/**
must_pass:
  - golden
  - unit
```

`verify` 会检查 git 已改文件是否超出 `allowed`（若 scope 文件存在）。

---

## AI 助手必须遵守

1. **改前**跑 `preflight`；失败先修回归，不叠加新功能。
2. **默认只改** `table_anomaly_rules.py`；动 bridge/UI/pipeline 须在 scope 里写明原因。
3. **不得删除** `tests/anomaly_golden/` 中已有用例；新增契约须加样本。
4. **不得**在未跑 `verify` 前说「已完成」。
5. 完成后输出：**改了什么 / 影响哪些规则 / verify 结果 / 你是否需重开 PDF**。

## 契约变更

若你明确要求修改「什么叫正常表」：

1. 先改 `docs/正常表契约.md`
2. 改 `tests/anomaly_golden/cases/*.json` 期望
3. 跑 `snapshot` 更新基准
4. 再改 `table_anomaly_rules.py`
