### 第 9+ 步：跨表去重 V3 — 尾头方向 + 结构完整性 🔥 ✅ 已完成

- **目标**：优化 `deduplicate_cross_tables`，从"全域双向前进删除"改为"尾头方向 + 后表结构完整性判断"
- **根因**：旧逻辑对源表每一行在全参考表中搜索匹配（any row vs any row），过于激进且缺乏方向性和结构判断
- **涉及文件**：
  - `codes/table_validator/rule_based_repair.py`（重写 `deduplicate_cross_tables` + 新增 `_has_complete_table_structure`）
  - `codes/ui/table_compare_manager.py`（调用方：相邻页支持 + reference_entries 格式）
- **核心策略**：
  1. 必须是紧相邻的表格（同页或相邻页，`abs(page_diff) <= 1`）
  2. 只检查"前表尾部 ↔ 后表头部"方向（前表最后 8 行 vs 后表前 8 行）
  3. 后表结构完整性判断：表头层（数值占比 < 0.3）+ 数据体（数值占比 >= 0.3）+ 汇总特征（合计/总计 或 2+数据行）
  4. 后表完整 → 从前表删除重叠行（后表拥有数据归属权）；后表不完整 → 不做任何删除
- **两个方向**：
  - Case A（源=前，参考=后）：检查源表尾部 vs 参考表头部，参考表完整 → 从源表删除
  - Case B（参考=前，源=后）：检查参考表尾部 vs 源表头部，源表完整 → 从参考表删除（原地修改）
- **子任务**：
  - [x] `_has_complete_table_structure()` — 3 条件结构完整性判断（表头+数据+汇总）
  - [x] 重写 `deduplicate_cross_tables()` — 尾头方向 + Jaccard 回退 + 紧相邻限制
  - [x] 调用方 `table_compare_manager.py` — reference_entries 格式 + 相邻页支持

### 第 10 步：表头缺失自动合成 🔥 ✅ 已完成

- **目标**：当 `repair_table_rules` 检测到表格无表头行时，自动合成默认表头，允许修复管线正常执行
- **背景**：延续型表格（如 table_011/012 从 table_010 分裂出）丢失列标题行，导致 `find_header_rows_bottom_up` 返回空 → 直接退出修复
- **涉及文件**：
  - `codes/table_validator/rule_based_repair.py`（新增 `_synthesize_header_if_needed` + 修改 `repair_table_rules`）
- **根因**：
  1. `data_start == 0` 时 `find_header_rows_bottom_up` 返回空 → 无表头 → 跳过全部修复
  2. `_needs_repair` 的 `data_start <= 1` 阈值拦截合成后的表格
- **修复方案**：
  1. 新增 `_synthesize_header_if_needed()`：4 条件检测（col0 文本标签 ≥2 + 数值行 ≥2 + 其余列数值占比 ≥50% + 前 3 行无纯文本表头行）
  2. 合成默认表头 `["项目", "列1", "列2", ...]` 插入 row[0]
  3. 合成后设置 `force=True` 绕过 `_needs_repair` 的 `data_start <= 1` 拦截
  4. 兜底：若 `find_header_rows_bottom_up` 仍返回空，强制使用 row[0] 作为表头
- **检测条件**（4 个 AND）：
